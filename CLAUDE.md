This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Personal portfolio site for Srivatsa Nayak, built with Next.js 13 (App Router), TypeScript and Tailwind CSS (no animation library — the few transitions are CSS). A single scrolling home page with anchor-linked sections (Home, Projects, Experience, About, Contact) plus two case study pages.

## Commands

Package manager is **yarn** (per README).

- `yarn install` — install dependencies
- `yarn dev` — run the dev server (`next dev`)
- `yarn build` — production build (`next build`)
- `yarn start` — run the production build (`next start`)
- `yarn lint` — lint via `next lint` (config extends `next/core-web-vitals`)

There is no test suite configured in this repo (no test script, no test runner dependency).

## Architecture

- **Routes**: the home page `src/app/page.tsx` is one scrolling page holding every section; the other pages are the case studies `src/app/projects/sql-visualizer/page.tsx` and `src/app/projects/route-check/page.tsx` (linked from project cards via the `caseStudy` field), built from the shared blocks in `src/components/case-study/CaseStudy.tsx` (`caseStudyMetadata`, `CaseStudyHeader`, `CaseStudySection`, `CaseStudyFigure`, lists, footer). There is also the `src/app/api/contact` route handler, plus metadata routes: `opengraph-image.tsx` and `apple-icon.tsx` (both edge runtime — the Node build of `@vercel/og` in Next 13.4 breaks `next build` on Windows), `icon.svg`, `sitemap.ts`, `robots.ts`. The public origin lives in `constants/site.ts` (`SITE_URL`) and feeds `metadataBase`, canonical URLs, the sitemap and the home page's `Person` JSON-LD — change it there when moving to a custom domain. Each page sets its own `alternates.canonical`. Each case study has its own preview image: `src/app/projects/<slug>/opengraph-image.tsx` (edge runtime) loads `og-screenshot.jpg` beside it and calls `renderCaseStudyOgImage` in `components/case-study/caseStudyOgImage.tsx`. The screenshot copy must be JPEG/PNG — the image renderer can't decode WebP. A page that sets `openGraph` without its own `opengraph-image.tsx` must list an image explicitly, because it replaces the root `openGraph`. Google Search Console ownership is verified by the file `public/google965930f607c9c5b7.html` (served at the site root) — keep it, or Search Console loses verification. `page.tsx` composes every section — Home/Hero (with `ImpactStrip`), Projects, Experience, About (with `TechStack`, headed "Skills"), Contact — as `<section id="...">` blocks stacked in one scrolling page; `constants/navlinks.tsx` lists them in the same order. Sections have no scroll-in animation: content is always visible (an earlier fade-in left sections blank in some browsers). `src/app/layout.tsx` defines the root HTML shell: a sticky `Navbar` header, the page content, and `Footer`, all inside `ActiveSectionProvider`. The page scrolls the window itself (no inner scroll container).
- **In-page navigation**: `Navbar` links point at `/#projects`, `/#experience`, ... so they work from the case study; on the home page the click handler finds the section and calls `scrollIntoView` instead of navigating. `Navbar` and `ActiveSectionProvider` live in the root layout, which persists across client-side navigation, so their effects re-run on `usePathname()` changes; `section[id]` has a `scroll-margin-top` in `globals.css` so headings clear the sticky header. `ActiveSectionProvider` (`src/components/layout/ActiveSectionProvider.tsx`) watches every `section[id]` and tracks scroll position: the active section is the last one whose top has passed a line 30% down the viewport, or the last section once the page is scrolled to the bottom; `Navbar` reads the result via `useActiveSection()` for its active-link underline.
- **Path alias**: `@/*` maps to `src/*` (see `tsconfig.json`). Use this for all intra-`src` imports.
- **Components** (`src/components/`) are organized by role:
  - `layout/` — chrome that wraps the page: `Navbar`, `Footer`, `Container` (max-width wrapper), `ActiveSectionProvider`.
  - `ui/` — typography/control primitives: `Heading`, `Paragraph`, `Highlight`, `DownloadResumeButton`, `CopyEmailButton`, `ArchitectureFlow` (the box-and-arrow diagram drawn from a project's `architecture` tiers, also used larger on the case study), `ShowMore` (collapsed list continuation used by `WorkHistory` after the first four bullets).
  - `sections/` — the section content blocks composed into `page.tsx`: `About`, `Contact`, `Products`, `ImpactStrip`, `TechStack`, `WorkHistory`.
- **Content-as-code pattern**: section content (projects, work history, skills, nav links, social links) lives in `src/constants/*.tsx` as typed data arrays, imported by components that render them (e.g. `constants/projects.tsx` → `Products` component, `constants/timeline.tsx` → `WorkHistory`, `constants/skills.tsx` → `TechStack`, `constants/navlinks.tsx` / `constants/socials.tsx` → `Navbar`). To change site content, edit the constants file, not the component.
- **Images**: project screenshots in `constants/projects.tsx` are static imports from `public/images/projects/` so Next.js can optimize them (and generate blur placeholders); skill logos in `constants/skills.tsx` are string paths to SVGs in `public/images/logos/`. Remote images are allowed from `images.unsplash.com` and `res.cloudinary.com` (see `next.config.mjs`).
- **Styling**: Tailwind CSS in a light "aeronautical chart" theme borrowed from the author's Aerothon project. Palette tokens in `tailwind.config.ts`: `paper` (page background), `sheet` (panels), `ink`/`ink-soft` (text), `rule` (borders), `magenta` (accent: active nav, route line, highlights), `chart` (blue), `go`/`hold` (success/error). Two self-hosted fonts via `next/font/local` (variable Latin `.woff2` files in `src/app/fonts/` with their OFL licences — `next/font/google` in Next 13.4 fails at random because Google sometimes returns font URLs without an extension): IBM Plex Sans (`font-sans`, the body default) for paragraphs and bullets at 16px, and JetBrains Mono (`font-display` for headings, `font-mono`) for headings, nav, buttons, labels (`.strip-label`) and tags (`.chip`). Project cards all use the `magenta` band; the hero `ImpactStrip` uses `go`. Cards, panels and screenshots use `rounded-lg`/`rounded-md`; buttons and chips `rounded-md`. Shared component classes live in `globals.css` under `@layer components`: `.strip`/`.strip-band`/`.strip-cell`/`.strip-label`/`.strip-input` (the "flight progress strip" card with a coloured left band, used by `ImpactStrip`, project cards and the contact form), `.panel`, `.chip`, `.btn-primary`, `.btn-secondary`.
- **Analytics**: `<Analytics />` from `@vercel/analytics/next` (v2, supports Next 13) in the root layout; it only reports on Vercel deployments with Web Analytics enabled in the project dashboard.
- **Not-found page**: `src/app/not-found.tsx` handles unknown URLs.
- **Contact form backend**: `src/app/api/contact/route.ts` validates input and sends mail via Resend (needs `RESEND_API_KEY` / `CONTACT_TO_EMAIL` in `.env.local` — see `.env.local.example`). `resend` depends on `@react-email/render`, which is not declared in its own package.json — keep it installed or the route fails to bundle.
- **Resume download**: `DownloadResumeButton` links to `/Resume_Srivatsa_Nayak.pdf` with the `download` attribute; the PDF is checked in at `public/Resume_Srivatsa_Nayak.pdf`. To update the résumé, overwrite that file (keep the name).
- **Email links**: the email address is shown via `CopyEmailButton` (copies to clipboard), not a `mailto:` link, because `mailto:` opens the visitor's OS default mail app. The address itself is the `EMAIL` constant in `constants/socials.tsx`.
